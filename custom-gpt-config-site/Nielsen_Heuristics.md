# Nielsen's 10 Usability Heuristics

Use these ten heuristics as the primary framework for evaluating the supplied website.

Do not force a finding for every heuristic. A heuristic may legitimately have no confirmed violation.

## 1. Visibility of System Status

The system should keep users informed about what is going on through appropriate feedback within a reasonable amount of time.

Evaluate:
- Loading and processing states
- Progress indicators
- Success and failure feedback
- Current state
- Saved/unsaved status
- Changes resulting from user actions

## 2. Match Between System and the Real World

The system should speak the users' language, using familiar words, concepts, and conventions rather than system-oriented terminology.

Evaluate:
- Labels and terminology
- Familiar concepts
- Error messages
- Information representation
- Natural ordering
- System jargon

## 3. User Control and Freedom

Users should have clear ways to undo, cancel, exit, go back, or recover from actions, particularly when actions are risky or irreversible.

Evaluate:
- Undo
- Cancel
- Back
- Exit
- Dismissal
- Confirmation for risky actions
- Recovery from mistakes

## 4. Consistency and Standards

Users should not have to wonder whether different words, situations, or actions mean the same thing. Interfaces should follow established platform and web conventions.

Evaluate:
- Terminology
- Component patterns
- Interaction behavior
- Visual conventions
- Web/platform conventions
- Success, error, and destructive-action conventions

## 5. Error Prevention

Good design should prevent problems from occurring in the first place, rather than relying only on error messages after the fact.

Evaluate:
- Constraints
- Defaults
- Validation
- Confirmation
- Safe actions
- Prevention of accidental submission

Keep this distinct from Heuristic #9, which focuses on helping users understand and recover from errors that have already occurred.

## 6. Recognition Rather Than Recall

Minimize the user's memory load by making relevant information, actions, and options visible or easily recognizable.

Evaluate:
- Recognizable controls
- Clear navigation location
- Visible options
- Understandable icons
- Previously entered information
- Available actions
- System state

## 7. Flexibility and Efficiency of Use

The interface should accommodate both inexperienced and experienced users and support efficient task completion.

Evaluate:
- Efficient workflows
- Shortcuts
- Sensible defaults
- Personalization
- Power-user support
- Repetitive task burden

Do not treat the absence of shortcuts as a violation unless efficiency is materially important in context.

## 8. Aesthetic and Minimalist Design

Interfaces should avoid information that is irrelevant or rarely needed. Every additional unit of information competes with relevant information and reduces its relative visibility.

Evaluate:
- Unnecessary information
- Visual clutter
- Competing hierarchy
- Excessive complexity
- Irrelevant content
- Density that interferes with task completion

Do not equate a minimalist visual style with good usability.

## 9. Help Users Recognize, Diagnose, and Recover from Errors

Error messages should be expressed in understandable language, clearly indicate the problem, and suggest a constructive path forward.

Evaluate:
- Error clarity
- Explanation of what happened
- Identification of the affected element
- Recovery instructions
- Preservation of user work
- Actionable next steps

## 10. Help and Documentation

Even when a system can be used without documentation, relevant help should be available when needed, easy to search, and focused on the user's task.

Evaluate:
- Availability of help
- Discoverability
- Conciseness
- Task orientation
- Understandability
- Contextual relevance

Do not classify every accessibility issue as Heuristic #10. Select the heuristic that most directly explains the usability problem.

---

# Evaluation Rule

For each potential issue, determine whether it is:
- An observation
- A potential concern
- A confirmed heuristic violation

Only confirmed violations should appear in the final findings unless the report explicitly contains a separate section for unverified observations.
